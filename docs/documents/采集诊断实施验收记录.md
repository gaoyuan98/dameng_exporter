`collector/testdata/collection_business_baseline.json` 来自实施前源码快照，比较指标描述中的名称、业务指标类型、完整标签、值、样本集合与SQL调用数。它不是用新实现生成的自我对照。新旧对比按blocking业务路径进行；fast另用可控接收者和同步信号验证策略与边界，不承诺不同调度下的样本集合逐项一致。

覆盖的主要失败边界：

- 两轮并发、两个数据源、交错错误的编号隔离；主机命令跨源并发，错误和样本保留各自数据源。
- 旧采集器有输出、无输出和报错均保持unknown；日志INFO/ERROR/DEBUG不改变明确业务路径的结果和阻塞模式样本。
- fast可转发、不可转发、未启用预算和超时；未超时满足samples+dropped_samples=生成数。业务success遇到丢弃仍计入known_failed_runs。
- 超时后关闭Registry输出通道，再让worker产生超过内部缓冲的1200条样本与晚到错误：无返回后写入、能后台排空退出、完成记录和日志计数不改写。
- 完成结果与预算均已就绪时优先完成；结果尚未就绪时如实超时；worker和公共入口panic均能归属并有序退出。
- blocking跨慢阈值继续等待；慢阈值早于/晚于fast预算；慢前置检查失败保留实际模式与预算，业务不启动；诊断WARN不增加业务日志计数。
- 自定义在全局fast下仍阻塞等待、转发样本，并记录blocking/0/none。
- 公共健康和节点类型共享实例并发抓取：每个入口每轮一条整体记录，逐源业务样本保持原行为；全部源不可用不伪造任务记录。
- 最慢三项稳定排序；非最慢零输出项仍在INFO名单；合法empty、unknown、skipped通过字段区分；重叠分类每项去重。
- 四项采集器连接检查、Query、Scan、rows.Err、正常与零行分支；表空间部分有效/全行无效、错误优先级及缓存异常；会话失败不补假零，系统信息保留首行与NULL/占位行为。

## 实施后审查

已逐项检查结果所有权、通道关闭、前后台转发边界、日志关联、计数、配置兼容和四项业务分支。审查后未发现尚未修正的阻塞性代码问题。审查中修正/确认的细节：

1. Query错误在原有错误处理之前分类。原错误处理可能等待确认性健康检查，不能让这段等待影响已经返回的查询错误分类。
2. worker退出时固定时间戳，后台耗时据此计算，避免将前台完成日志或后台等待者调度延迟算成worker执行时间。
3. 超时转发者在读取样本后再次优先检查停止信号；前台只在forwardDone确认后返回，排空期间不再改写前台计数。
4. 进行中慢提示使用不带业务Hook的logger，前台结束前停止并等待观察任务退出；避免自计数和轮次结束后的慢提示。
5. 参数指南原先将fast描述为整次请求严格超时，并借用全局超时判慢，已同步为本版实际预算与独立慢阈值口径。

以下为方案明确保留的限制，未混入本次诊断改造：旧缓存缺少完整性标记；反序列化失败后切片可能残留数据；部分读取仍可能写入缓存；多数采集器业务结果尚未分类；真实DM查询可能在前台返回后继续运行。系统信息仍只读取首行，无记录仍输出基础占位样本。业务完整性不能从样本数或日志条数推断。

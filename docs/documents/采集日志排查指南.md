# 采集日志排查指南

每次 Registry 采集都有独立的 `scrape_id`。默认 INFO 日志可查看本轮总耗时、最慢三项、零样本计数与最多 20 项明细和关联错误。`phase=collection` 只表示采集阶段，不包含 HTTP 编码、传输，也不证明客户端已收到指标。

## 先看轮次汇总

正常情况下，新增 INFO 诊断事件每轮两条：`scrape_started` 和 `scrape_finished`。存在失败、部分读取、快速超时、panic、跳过、丢弃样本、慢项、观察到的业务 WARN/ERROR 或不可用数据源时，结束汇总为 WARN。正常的逐项开始、完成及缓存命中提示在 DEBUG；启动和独立后台健康消息另外存在。

| 汇总字段 | 含义 |
| --- | --- |
| `collection_duration_ms` | 进入本轮采集至所有前台任务结束、停止转发并形成快照的总耗时 |
| `recorded_runs` | 实际记录数，包括公共采集器；不等于应执行任务数 |
| `samples` | 成功转发给本轮 Registry channel 的业务样本数 |
| `known_failed_runs` | outcome=failed/partial、execution=timeout/panic 或丢弃过样本的记录数，每项只计一次 |
| `unknown_runs` | outcome=unknown 的记录数，不等于故障数 |
| `observed_error_runs` | 观察到业务 ERROR 的记录数，独立于业务结果 |
| `skipped_runs` | 前置检查失败、业务未开始的记录数 |
| `slow_runs` | 总耗时达到本项慢提示阈值的记录数 |
| `zero_sample_runs` | 实际记录中 samples=0 的数量，包括合法 empty、unknown、失败和跳过 |
| `zero_sample_collectors` | 按 scope、datasource、collector 排序后的前 20 个零样本项；包含 execution、outcome、reason；INFO/WARN 均使用该上限 |
| `zero_sample_collectors_omitted` | 未展示的零样本项数；等于 zero_sample_runs 减去已展示数；未省略时为 0 |
| `unavailable_datasources` | 结束时不可用的已启用数据源名称，去重排序；不代表整轮均不可用 |
| `slowest` | 耗时最长的三项，不足三项则全部展示；含实际 mode、timeout_ms、timeout_scope、execution、outcome 和样本数 |

上述计数存在重叠，例如快速超时同时计入 known_failed_runs 和 unknown_runs，不能相加求总数。数据源没有进入健康池时，不会伪造几十条 skipped；此时看 unavailable_datasources 和原有健康指标。

默认汇总不输出全量 `results`。零样本总数和所有分类计数均按全部记录计算，明细截断不影响计数、最慢三项和告警级别。零样本、unknown 或明细被省略本身不会提升日志级别。省略数量大于 0 时，启用 DEBUG 并按 scrape_id 筛选逐项完成记录查看全量；未展示的异常项仍有独立 WARN 完成记录。上限约束名单项数，不保证整条日志的固定字节数。

## 看执行状态与业务结果

每项完成事件为 `collector_finished`，字段平铺。`execution` 记录执行器行为，`outcome` 记录业务完整性，二者分开。

| execution / outcome | 解释 |
| --- | --- |
| completed / success | 已实现结果契约，完成其现有业务要求 |
| completed / empty | 已确认查询和读取完整，按该业务允许无输出 |
| completed / partial | 读取不完整，但生成了可用的部分结果 |
| completed / failed | 业务查询或读取失败，没有形成可用结果 |
| completed / unknown | 旧采集器未分类，或缓存/占位等路径无法证明完整性 |
| skipped / unknown | 适配器前置检查失败，reason=datasource_unavailable，业务未开始 |
| timeout / unknown | fast 的前台等待预算到期，reason=frontend_timeout，后台可能继续 |
| panic / failed | 捕获执行异常；原异常和堆栈关联同一轮 |

`observed_warning_logs`、`observed_error_logs` 仅统计当前日志级别下实际观察到的业务日志，不用于推断 outcome。慢提示等诊断日志不反向计入业务告警。仅开启 ERROR 会隐藏汇总和 WARN 线索，但不会改变明确业务路径的结果分类。

`dropped_samples` 是 fast 非阻塞转发中已确认丢弃的数量，与读取是否完整分开。outcome=success 也可能丢弃过样本，此时 known_failed_runs 仍计入。前台结束后的后台排空量不追加入前台样本或丢弃计数。

首批只有以下四项返回明确业务结果：

- `TableSpaceInfo`、`TableSpaceDateFileInfo`：新查询完整且有行为 success，完整零行为 empty。Scan 或 rows.Err 错误按有效行判断 partial/failed，同时存在时 rows_error 优先；本轮仍可输出有效行，但读取不完整时不更新缓存，下一轮重新查询。缓存命中为 unknown/cache_unverified，data_origin=cache。缓存解析失败后丢弃本地解码残留，新查询按实际完整性判定 success/empty/partial/failed，保留 cache_fallback=true；不再返回 cache_recovery_unverified。完整结果序列化成功后才覆盖共享缓存，完整零行同样允许缓存；仅序列化失败不改变已经输出的业务结果。
- `DBSessionsStatus`：完整读取为 success，零行也按原业务补 ACTIVE/IDLE=0。Query、Scan、rows.Err 失败均为 failed，不输出部分结果或伪造零值。
- `DBSystemInfo`：成功读取首行为 success，NULL 字段按原逻辑省略对应 CPU/内存指标。无行仍保留原数值为 1、空信息标签的基础占位样本，结果为 unknown/no_row_placeholder。只读取首行，不承诺检查后续行。

其余采集器均为 unknown/legacy_unclassified；有样本、有错误或无输出都不会自动改判。查询返回的超时为 completed/failed/query_timeout；分类依据错误类型和查询上下文，不猜测 DM 错误码。权限错误一般为 query_error，具体原因看同轮原始错误。

自定义 SQL 必须完整读取后才交付该条查询的结果。Query、Scan 或 rows.Err 失败时丢弃该查询的部分行，并通过现有错误处理链写入关联 ERROR；其他已成功查询的结果保留，后续配置项继续原有循环。超时或数据源降级仍可能使后续查询失败；新识别的读行错误可能触发现有确认性探活或快速降级。自定义采集器的 outcome 仍为 unknown，完整零行不补零。

## 数据源与计时归属

关联字段为 `scrape_id`、`scope`、`datasource`、`collector`。datasource 是配置名称；当业务标签不同，另有 datasource_label，对照原有指标标签。

经多数据源适配器执行的内置采集器、主机进程和自定义采集均为 scope=database，每个实际执行的数据源各一条记录。主机进程命令失败仍按原逻辑输出零，结构化 ERROR 带 process_name、原始错误及当前数据源；其 outcome 仍为 unknown。

BuildInfo、DatasourceHealth、DbNodeTypeInfo 等公共入口为 scope=exporter、datasource 为空、mode=direct，每个入口整体一条；健康和节点信息原有逐源业务标签保持不变，不拆成虚构的逐源耗时。并发抓取不会向共享公共实例写入轮次上下文。

`duration_ms` 从该项开始前置检查计时，包含连接检查、连接获取、查询、读行、处理、错误处理和前台转发。并发任务耗时不能相加作为 collection_duration_ms；多条 SQL 共用一个采集器时，也不能用该项耗时当作单条 SQL 或数据库服务端执行时间。

## 慢提示与快速超时

全局 TOML 参数放在 `[[datasource]]` 之前：

```toml
# 仅控制提示；0 关闭，不改变任何查询或采集超时。
collectorSlowThresholdMs = 5000
```

旧配置缺省为 5000ms；显式 0 会在加载、命令行合并、保存和密码自动加密后保留。负数和换算为 time.Duration 溢出的值在加载校验时拒绝。该参数没有新增命令行开关。

阈值从前置检查开始计算。达到阈值时如果尚未完成，至多输出一次 WARN `collector_slow`，带 threshold_ms、duration_ms、still_collecting=true；只提示，继续等待原流程。前台完成会停止观察任务，最终 slow 以实际耗时比较，临界时可能仅有完成明细而没有进行中提示。0 关闭提示和 slow 标记，计时与最慢三项仍保留。

| mode | timeout_ms / timeout_scope | 行为 |
| --- | --- | --- |
| blocking | 0 / none | 等待采集和转发完成；独立慢阈值不会取消它 |
| fast | 生效的 globalTimeoutSeconds × 1000 / worker；未启用预算时 0 / none | 沿用原 worker 阶段等待预算，前置检查不计入预算；总 duration_ms 可能更大 |
| direct | 0 / none | 公共入口原行为，不强加数据库检查或 fast 预算 |

自定义指标即使全局为 fast 仍按原 blocking 行为执行。模式和预算在前置检查前固定，skipped 也保留配置预算，但该预算尚未进入等待阶段。这里的预算不覆盖 HTTP 编码传输或整个转发阶段，worker 已结束后等待转发结束不会再追加取消行为。

fast 超时先停止向本轮转发并等待确认，再冻结唯一一条 timeout/unknown 完成记录。后台继续产生的样本被排空；晚到错误和 `collector_background_finished` 仍使用原 scrape_id。后台事件带最终 outcome 和 background_duration_ms（原 run 开始到 worker 实际退出的总时长），不改写已经输出的汇总。并发和日志开销可能使临界附近的完成/超时、转发/丢弃不同，不能要求每次精确相同。

## 日志筛选

查看总耗时、分类、零样本和最慢三项：

```bash
jq -c 'select(.msg == "scrape_finished") | {scrape_id, collection_duration_ms, known_failed_runs, unknown_runs, zero_sample_runs, zero_sample_collectors, zero_sample_collectors_omitted, slowest}' logs/dameng_exporter_2026-11-12.log
```

复制某条汇总编号，查看该轮原始错误、完成记录和晚到后台退出：

```bash
jq 'select(.scrape_id == "替换为实际编号")' logs/dameng_exporter_2026-11-12.log
```

只有开始、没有结束时，先查进行中的慢提示：

```bash
jq 'select(.msg == "collector_slow") | {scrape_id, scope, datasource, collector, mode, timeout_ms, timeout_scope, duration_ms, threshold_ms}' logs/dameng_exporter_2026-11-12.log
```

临时启用 DEBUG 后可按轮次恢复每项明细：

```bash
jq -s 'map(select(.msg == "collector_finished" and .scrape_id == "替换为实际编号")) | sort_by(-.duration_ms, .datasource, .collector)' logs/dameng_exporter_2026-11-12.log
```

INFO 下只保留异常或慢项的 collector_finished。若只有 unknown 零输出而无原始错误，先查开关、适用节点和缓存；不能凭 samples=0 宣称查询失败。

零样本名单被省略时，启用 DEBUG 后查看新轮次的完整零样本明细（启用前已被过滤的历史 DEBUG 无法恢复）：

```bash
jq -s 'map(select(.msg == "collector_finished" and .scrape_id == "替换为实际编号" and .samples == 0)) | sort_by(.scope, .datasource, .collector)' logs/dameng_exporter_2026-11-12.log
```

不完整查询不再被缓存，因此持续失败时后续轮次会重新回源，查询量可能高于旧版错误缓存命中的情况。缓存仅存于进程内，正常替换程序并重启会清空旧缓存，无需数据迁移。

## 试运行与回滚

先保留原二进制、配置、面板及同输入指标/日志。单个测试或低风险实例替换候选二进制，旧配置应能直接加载。正常场景连续观察三轮，核对编号、耗时、零样本名单和模式；在测试源分别复现权限不足、慢查询和 fast 超时，按同一编号找齐原始错误、前台完成及后台退出。临时开启 DEBUG 核对全量明细后恢复 INFO，比较日志量和单轮大小。

blocking/direct 按固定输入比较完整指标名、类型、标签、值、样本集合和 SQL 次数；fast 按受控时序核对非阻塞策略、实际转发/丢弃计数和返回后不再写入。模拟驱动不能代替真实 DM 查询取消试验，需保留现场后台退出证据。若出现指标、策略、配置、竞争或额外 SQL 回归，停止推广，恢复原二进制和原配置；无数据库结构迁移，面板单独处理。

诊断初版的 status/results、metrics、collector_runs 等字段已调整，外部日志解析规则需要同步更新。本轮新增 zero_sample_collectors_omitted，并将默认名单限制为 20 项；业务指标名称和标签沿用原定义，坏缓存回退、部分结果缓存和自定义读行失败路径按上述规则修正。当前修复、验证和审查情况见[问题修复与收敛实施方案](采集诊断问题修复与收敛实施方案.md)，前阶段记录见[采集诊断实施验收记录](采集诊断实施验收记录.md)。

## 实施结果

| 范围 | 实际行为 |
|---|---|
| 控制台 | 中文事件、固定顺序、竖线分隔；INFO/WARN/ERROR 隐藏通用 caller；DEBUG 保留位置 |
| JSON 文件 | 保留英文事件及 ts/level/caller，一条业务事件只写一次 |
| 正常 INFO | 每轮一条摘要，保留耗时、任务、SQL、样本和轮次；异常计数发生时追加 |
| SQL 失败 | ERROR 摘要和同级完整 SQL 详情成组输出；WARN/ERROR 配置仍能看到错误原文 |
| DEBUG | 分别构造开始与完成字段；文件仅开始时保留一次 SQL；API 分项集中到 api_ms |
| 慢采集 | 原阈值、候选、排序、刷新条件及最多五条排名保持；快照使用 snapshot_id/top_emitted_count |
| fast 模式 | 每个 run 首次 Detach 独立输出一次前台超时 WARN；后台事件保留原关联及 phase=background |
| 启动 | 合并重复成功提示，INFO 输出配置摘要及完整指标访问 URL，DEBUG 使用明确字段记录配置且排除密码 |
| 其他业务提示 | 规范 zap 字段传参；SYSJOB 提示简化并关联 SQL 原始错误，不推断应该执行何种数据库初始化操作 |
| 文档 | README、参数配置指南、采集日志排查指南及实施方案同步 |

现有 logLevel 配置保持原值；本次没有添加配置项或依赖。采集 SQL、参数、执行顺序、指标/标签、缓存、健康处理和等待/取消策略作为回归约束。

## 审查中修复的问题

1. 已知事件的部分内部字段仍落入兼容输出，导致慢采集和失败行尾部出现英文冗余信息。为这些字段明确选择展示位置；错误阶段、读取状态、数据来源和 DEBUG 执行阶段使用统一中文显示，文件保留原值。
2. 输出分组若分别写主行和详情，并发时可能交错。现在同一事件一次 Write，所有 With 派生日志器共享锁；文件目标也统一加锁。80 个并发事件检查两行始终相邻、文件恰好 80 条且逐条 JSON 有效。
3. With 中可变的反射对象若延迟读取，后续修改可能改变已继承的上下文。现在在 With 时固定其值，保留大整数精度，测试覆盖对象仅求值一次、嵌套数据修改、字段覆盖及 namespace。
4. 自定义 core 需保留 zap 的输出边界行为。已补上 fatal/panic 退出前刷新，保留命名日志器及显式 entry 堆栈，验证短写、写失败、Sync 错误，以及任一输出失败时另一目标仍收到事件。
5. 前台超时警告必须属于前台，且不能重复。上下文在设置 detached 前固定；测试验证首次 Detach 只发一次 WARN。后台 SQL 错误及退出仍有 background 标记，不能回写最终轮次计数。
6. SQL、错误和栈中的换行及控制字符必须可逆。错误 SQL 超过 100KB 时仍不截断；控制台逐值转义，文件 JSON 完整；普通 SQL 错误没有自动堆栈，panic 显式栈只输出一次。
7. 自定义采集器在全局 fast 下仍应采用 blocking。模式字段从完成事件移出后，将对应回归断言扩展至开始事件，并检查没有 detached 状态或超时警告，避免仅检查字段缺省而削弱原测试。
8. 启动监听保留可直接打开的指标 URL，避免精简后只剩端口和路径。文件保留原监听地址与路径；生成访问链接时处理仅端口、IPv4/IPv6 通配地址和指定主机。

核心状态锁释放后才做格式化和输出；没有把新的日志 I/O 放进 SQL 计时 API 或诊断状态锁内部。慢诊断组沿用独立的 output 锁，数据库操作不持有该锁。

| 场景 | 控制台展示行 | 文件逻辑事件 | 完成摘要显示字符数 |

| normal | 1 | 1 | 77 |
| error | 3 | 2 | 96 |

显示字符数按 Unicode 字符统计，包含时间、级别和关联；不是终端占用列宽。错误场景的两个文件事件分别为 sql_error 和 scrape_finished，控制台额外行是同一错误事件的完整 SQL 详情。

将用户粘贴日志中的 scrape_finished 使用相同值、相同头部和紧凑 JSON 序列化进行对照：业务字段从 22 个减至 7 个，含头部和换行从 625 字节降至 258 字节，减少 58.7%。该轮有两个非零异常计数字段；正常轮次只需五个核心字段。计算口径与结果保存于 `/tmp/dameng-log-size-review.json`。

文件每轮诊断 INFO 最多 12 个逻辑事件，控制台计入 Top 的 SQL 详情后最多 22 条展示记录；错误、超时警告、状态变化和后台退出另计。SQL、原始错误、长名称允许超出普通摘要长度，不通过截断满足长度指标。

## 性能结果及代价

同一台 darwin/arm64、Apple M5 环境，每项运行三次，以下取中位数。短基准受到调度、缓存及机器负载影响；这些数据用于披露代价和核对输出量，不作为生产吞吐承诺。

`BenchmarkCollectionDiagnostics` 使用 INFO JSON core，不包含控制台或实际磁盘 I/O，也没有实际数据库网络开销：

| 场景 | SQL/轮 | 逻辑日志/轮 | 改前日志字节/轮 | 改后日志字节/轮 | 改前 ns/op | 改后 ns/op |
|---|---:|---:|---:|---:|---:|---:|
| single | 1 | 1 | 557.6 | 172.1 | 17,225 | 21,368 |
| multi | 40 | 1 | 559.1 | 173.2 | 155,987 | 164,341 |
| thousand | 1000 | 1 | 561.3 | 175.2 | 2,522,639 | 3,067,137 |
| concurrent | 40 | 1 | 559.1 | 173.2 | 89,980 | 74,785 |

该基准中正常摘要字节减少约 69%，SQL 调用数和每轮逻辑日志数一致。ns/op 波动较大，不能据此断言总体 CPU 性能改善。single 的内存分配从约 30.9KB/226 次降至约 19.9KB/186 次；大量查询时收益相对更小。

`BenchmarkConsole` 对相同事件字段比较旧 zap 控制台编码与新的中文渲染，覆盖正常摘要、SQL 错误、慢 SQL、DEBUG 开始和 DEBUG 完成，并报告展示行数及字节数：

| 场景 | 原编码 ns/op | 中文渲染 ns/op | 原显示字节/事件 | 新显示字节/事件 | 新分配 B/op、次数 |
|---|---:|---:|---:|---:|---|
| 正常摘要 | 445.7 | 988.8 | 180 | 111 | 1272、23 |
| SQL 错误 | 734.8 | 3512 | 831 | 825 | 5050、29 |
| 慢 SQL | 730.7 | 3421 | 829 | 825 | 5050、29 |
| DEBUG 开始 | 833.9 | 1521 | 905 | 161 | 1938、36 |
| DEBUG 完成 | 718.8 | 2081 | 327 | 174 | 2716、37 |

普通摘要新渲染约 1 微秒，原编码约 0.45 微秒；新渲染需要更多内存分配。错误及 Top 附完整 SQL 详情，控制台由一行变成两行。DEBUG 开始不再向控制台展开成功 SQL，因此显示字节明显减少，但文件仍保存 SQL。这是固定输入的格式化基准，不能替代所有原事件字段的端到端字节对比。

已去掉缺失字段的无效标记分配、使用标量快速格式化并合并字符串构造，普通摘要的首次实现约 3.2 微秒降至约 1 微秒。中文控制台的可读性仍有额外处理代价，没有把文件变短解释为 CPU 必然更省。基准使用内存 sink，不衡量终端速度；实际磁盘/终端和高频 DEBUG 的影响需在目标部署环境评估。

## 兼容与验证边界

控制台已从尾部 JSON 改为中文文本，自动采集应读取文件 JSON。旧字段消费者需按排查指南迁移：query_sequence、旧 Top 管理字段、平铺 API 耗时字段已删除或替换；正常状态及未发生的异常计数按事件契约省略。未知行数为 null、无 deadline 为 null、已知零行为 0、预算耗尽为 0，语义保持区分。

本次没有启动连接真实 DM 的服务，没有修改数据库权限或功能，也没有执行部署。正常连接、权限/模式错误、慢查询、驱动取消、前台超时后后台退出、连接恢复以及实际日志轮转仍需目标环境验证。构建产物保存在临时目录，源码变更可直接审阅。
